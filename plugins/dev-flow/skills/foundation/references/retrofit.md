# Retrofit

Loaded from `foundation` when the mode is `retrofit`: a foundation run over a plan that
already exists, to find the requirements and records it is missing. It runs in the session
that owns the target repo's series, never from a neighbour's.

## Input

The existing series (every serial, in order, with each `Supersedes` applied), the repo's
docs, its `CLAIM.md` when it has one, and the operator decisions the series records.

## Output

The target series' next serial, `NN_retrofit.md`, opening with a `Supersedes` block
(`Nothing — purely additive` unless it overturns a statement), with:

1. **Each artifact of `references/artifacts.md` populated from what exists.** Every line
   cites its source (`file:line`, a decision's number, a commit) or is marked `(inferred)`.
   A decision recorded as "confirmed by the operator" is a source; a plan statement nobody
   confirmed is inferred.
2. **A gap list**: an artifact with nothing behind it (no quality scenarios, no glossary), a
   requirement no feature serves, a one-way decision with no ADR, a quality that exists only
   as a decision or as plan text, a feature with no test plan.
3. **The gaps as decisions** for the operator, each put per the `operator-interaction:decisions`
   skill when the session lists it: write the missing artifact (and from what), hold it, or
   accept the gap as a non-goal.

The `INDEX.md` regenerated by this pass gains the Foundation block (`references/state.md`),
its phases marked `retrofit` in the Gate cell until the operator answers the gap decisions.
From there the series is a foundation series: later answers are moves, and gates run as in
a new run.

## What a retrofit checks

Recall only: whether it finds the gaps already known. Whether the artifacts help is tested
by new-project runs, one `lite` and one `full`.
